### Introduction
The **Curve Ball** challenge is an elliptic-curve cryptography (ECC) challenge that asks us to recover a secret scalar ($k$) used in an elliptic-curve multiplication. At first glance, the challenge looks like a standard **elliptic curve discrete logarithm problem (ECDLP)**, which is believed to be computationally infeasible for secure curves. However, the challenge contains a subtle but fatal vulnerability in how the curve parameters are chosen. This vulnerability allows the problem to be broken efficiently using the **Pohlig–Hellman algorithm**.

### Challenge Setup
In this challenge, we were given an instance which when we connected to the server, we got the below information: 

![Challenge Setup](/images/pascal.png)

Here, they've given us: 
- The elliptic curve equation
- The prime size field $p$
- A number $n$
- A base point $G$
- A public point $Q$ which refreshes at every new instance

What the server internally does:
```python
secret = random_value % n
Q = secret * G
```
which means that the system computes $Q=kG$ and prints $G$ and $Q$.

our job is to recover $k$ from $(G,Q)$.

This is the **Elliptic Curve Discrete Logarithm Problem (ECDLP)**:

> Given $G$ and $Q=kG$, find $k$.

In secure ECC, this should be computationally infeasible for large groups.

### The Vulnerability

As we can see, the relation between the prime field size $p$ and the number $n$ is that:

* $p=1844669347765474229$
* $n=1844669347765474230=p+1$
* $n=p+1$

This number is intended to represent the order of the subgroup generated by $G$.
And since $n$ is of the form $p+1$, this means that $n$ is **smooth**. Which basically means that, when we factor $n$, it will reveal small prime numbers. i.e., $n$ is composed of small factors.

Factoring $n$ reveals:
$$n=2 \cdot 3^{2} \cdot 5 \cdot 7 \cdot 11 \cdot 13 \cdot 17 \cdot 19 \cdot 23 \cdot 29 \cdot 31 \cdot 37 \cdot 41 \cdot 43 \cdot 47$$

**This is the fatal mistake.**
ECC is secure only when the group (or subgroup) order contains a **large prime factor**. If the order is smooth, the ECDLP becomes easy.

### The Exploit

As mentioned before, ECDLP is hard *when the group has a large prime factor*.  
But if the group order is smooth, **Pohlig–Hellman breaks the discrete log efficiently** by reducing the problem into many small discrete logs.

#### The Pohlig Hellman Algorithm

Pohlig–Hellman is an algorithm for solving **discrete logarithms** in a finite cyclic group when the **group order factors into small primes**. It turns one “big” discrete log into many small ones, then joins the answers back together with CRT.

Discrete log problem (DLP): in a cyclic group $G=\langle g\rangle$ of order $n$, given
$$h=g^x \quad (\text{multiplicative group})$$
or 
$$H=xG$$ 
on an elliptic curve, i.e. additive notation,  
find $x$ modulo $n$.

**Pohlig–Hellman** solves for $x$ efficiently when:
$$n=\prod_{i} p_i^{e_i}$$ 
and the primes $p_i$ are “small enough” that the subproblems are easy and it reconstructs it using CRT.

In our case, the DLP is in the form of:
$$Q=kG$$
directly, Pohlig–Hellman:

1. Factors the group order:
   $$n=\prod_i p_i^{e_i}$$
2. For each prime power $m=p_i^{e_i}$ computes:
   $$k \bmod m$$
3. Reconstructs $k \bmod n$ using the **Chinese Remainder Theorem (CRT)**.

and we can use Pohlig Hellman here, as:
- The group is cyclic 
- The group order $n$ is known
- The group order factors into small prime powers

All of these conditions are satisfied in Curve Ball.

Let:
- $\text{ord}(G)=n$
- $m \mid n$
- $h=n/m$
    
Define:
$$G_m=hG, \quad Q_m=hQ$$

Then:
$$Q_m=kG_m$$
$$\text{ord}(G)=n$$
$$\text{ord}(hG)=\frac{n}{\gcd(n,h)}=m$$

So:
- $G_m$ generates a subgroup of size $m$
- The equation $Q_m=kG_m$ only determines $k \bmod m$
    
##### Solving the Small Discrete Logs
Since each $m$ is small (at most 47 or $3^2=9$):

- The discrete log in each subgroup is trivial
- Sage’s `discrete_log()` can solve it instantly
    
Each solution gives one congruence:
$$k \equiv k_i \pmod{m_i}$$

code:
```python
#Iterates over each power divisor 'm'
for prime, exp in factors:
    m = prime^exp
    h = n // m
    Gm = h * G #creates a generator of a small subgroup of size m
    Qm = h * Q
    km = discrete_log(Qm, Gm, operation="+") #computes k mod m
    mods.append(m) #Stores the congruences
    logs.append(km)
```

Once all congruences are known, the **Chinese Remainder Theorem** guarantees a unique solution modulo $n$:

$$k \equiv k_1 \pmod{m_1}, \quad k \equiv k_2 \pmod{m_2}, \quad \ldots$$

CRT combines these into the full secret $k$.

code:
```python
k = crt(logs, mods) % n   #reconstructs the k value using CRT
```

And after recovering the secret $k$, we need to input it in the instance in hexadecimal and then, we'll obtain the flag!
